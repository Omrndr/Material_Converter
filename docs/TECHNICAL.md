# Technical details

This document is for developers. For installation and usage, see the [README](../README.md).

## Overview

Material Converter is a Manifest V3 WebExtension. It reads the property table of a MatWeb data sheet directly from the
page's HTML (no OCR, no AI, no server), converts it and writes:

- an **ANSYS Engineering Data library** (MatML 3.1–based XML, the format Workbench imports and exports), and
- optionally a **detailed generic XML** with everything on the page.

The same source code runs on Firefox and on Chromium-based browsers (Chrome, Edge); a build script produces a package
for each.

## How it works

1. **Reading the page** — the toolbar panel injects `lib/matweb-parser.js` into the active tab (`activeTab` +
   `scripting` permissions, granted when the user clicks the toolbar button). The parser walks
   `table.tabledataformat`, groups rows by section header (Physical, Mechanical, Thermal, …) and parses every cell into
   value / range / qualifier (`>=`, `<=`) / unit and conditions such as `@Temperature 371 °C` or
   `@Thickness 88.9 - 102 mm`. Rows with an empty first cell are additional data points of the previous property.
2. **Storing** — parsed materials, categories and settings are kept in `storage.local`. Materials are identified by
   their MatGUID, so adding the same page again updates the entry instead of duplicating it.
3. **Writing** — `lib/ansys-writer.js` maps fields, converts units and produces the library XML. Downloads go through
   the background script (on Chrome/Edge via an offscreen document, because service workers cannot create blob URLs)
   using `downloads.download` with a fixed path inside the Downloads folder and `conflictAction: "overwrite"`, so the
   file ANSYS points to is replaced in place.

## ANSYS property mapping

| MatWeb | ANSYS | Notes |
|---|---|---|
| Density | Density | g/cc → kg/m³ |
| Modulus of Elasticity + Poissons Ratio | Elasticity (Isotropic) | ν is derived from Shear Modulus if missing; K and G are computed |
| Tensile Strength, Yield / Ultimate | Tensile Yield / Ultimate Strength | MPa → Pa |
| Compressive Yield Strength / Compressive Strength | Compressive Yield / Ultimate Strength | MPa → Pa |
| CTE, linear | Coefficient of Thermal Expansion (Secant) + Zero-Thermal-Strain Reference Temperature | "@ 20–100 °C" style ranges become a temperature table |
| Specific Heat Capacity | Specific Heat (Constant Pressure) | J/g-°C → J/kg-°C |
| Thermal Conductivity | Thermal Conductivity (Isotropic) | |
| Electrical Resistivity | Resistivity | ohm-cm → ohm-m |

- Density, elasticity, specific heat and conductivity are written as temperature tables when at least two temperature
  points exist; strengths use the room-temperature (unconditioned) value.
- For ranges (e.g. "670 – 1240 MPa") the MatWeb average from the comment column is used, otherwise the midpoint;
  this is noted in the material's `Description`.
- Thickness-dependent values, hardness and composition are not transferred (they are in the generic XML).
- The mapping lives in `FIELD_MAP` in `extension/lib/ansys-writer.js`.
- Property and parameter names, units and the temperature-table layout follow a real ANSYS 2023 R1 export
  (`test/reference/`). During development the generated files were also checked with ANSYS's open-source MatML
  reader ([pymaterials-manager](https://github.com/ansys/pymaterials-manager)); this check is not part of the automated tests.

## Categories

Each user category is written as its own ANSYS library file named after the category
(`<folder>/<category name>.xml`), with `Category: <name>` in the file's `Notes`. Category files are written only when
the user presses **Download category as ANSYS library**; afterwards the page shows whether the downloaded file is still
up to date (`changedAt` vs. `lastWrittenAt`).

## Generic XML format

```xml
<Material source="MatWeb" sourceUrl="..." exportedAt="2026-10-02T12:00:00.000Z" formatVersion="1">
  <Name>Aluminum 7075-T6; 7075-T651</Name>
  <Categories><Category>Metal</Category>...</Categories>
  <Notes>...</Notes>
  <KeyWords><KeyWord>UNS A97075</KeyWord>...</KeyWords>
  <PropertyGroups>
    <PropertyGroup name="Mechanical Properties">
      <Property name="Tensile Strength, Ultimate">
        <DataPoint>
          <Metric value="572" unit="MPa" text="572 MPa"/>
          <English value="83000" unit="psi" text="83000 psi"/>
          <Comment>AA; Typical</Comment>
        </DataPoint>
        <DataPoint>
          <Metric qualifier="&gt;=" value="462" unit="MPa" text="&gt;= 462 MPa">
            <Condition name="Thickness" min="88.93" max="102" unit="mm"/>
          </Metric>
          ...
        </DataPoint>
      </Property>
    </PropertyGroup>
  </PropertyGroups>
</Material>
```

- A single value uses `value`, a range `min` + `max`; `>=`, `<=` are in `qualifier`.
- Conditions (temperature, thickness, …) are `Condition` elements.
- `text` keeps the raw text from the page; non-numeric values (e.g. "Yes") only have `text`.

## Browser differences

| | Firefox | Chrome / Edge |
|---|---|---|
| Background | background page (`background.scripts`) | service worker |
| Download URL | blob URL in the background page | blob URL from an offscreen document (`offscreen` permission) |
| Icons | SVG | PNG (16–128 px) |
| Manifest | `browser_specific_settings.gecko` | generated by `scripts/build.mjs` |

Messages to the background script are answered with `sendResponse` (Chrome does not accept a returned Promise).

## Internationalization

Texts live in `extension/_locales/<lang>/messages.json` (`en` default, `tr`). HTML elements use `data-i18n`,
`data-i18n-html`, `data-i18n-placeholder` and `data-i18n-title`; scripts use `UI.t(key, subs)` and `UI.tn(key, n)`
(which picks `<key>_one` for a count of one). XML files are always written in English.

## Building

```bash
npm install            # test dependencies only (Playwright)
npm run build          # dist/firefox, dist/chromium and zip packages
npm run build -- --no-zip
```

## Tests

```bash
npm test               # parser, writers and store in a real browser DOM; compares with test/expected
npm run test:update    # update expected outputs after an intentional change
npm run lint           # Mozilla web-ext lint
```

**Firefox end-to-end** (`test/firefox/e2e.py`) loads the extension into real Firefox, clicks the toolbar button,
uses the panel and the library page and checks the downloaded files. Requests to `www.matweb.com` are routed to a local
fake server, so no internet access is needed. Runs with the English interface.

```bash
pip install selenium
# Without Firefox/geckodriver on Linux: micromamba create -p ./ffenv -c conda-forge firefox geckodriver
FIREFOX_BIN=./ffenv/bin/firefox GECKODRIVER=./ffenv/bin/geckodriver xvfb-run -a python test/firefox/e2e.py
```

**Chromium end-to-end** (`test/chromium/e2e.mjs`) loads the Chrome/Edge package into real Chromium and covers page
reading, service worker + offscreen downloads, subfolders/overwriting, the library page and categories. Chromium's
toolbar button cannot be clicked by automation, so the test uses a copy of the extension with a host permission for
MatWeb and opens the panel in a tab. Runs with the Turkish interface.

```bash
npm run build -- --no-zip
xvfb-run -a node test/chromium/e2e.mjs      # CHROMIUM_BIN can point to another browser binary
```

Your own saved MatWeb pages can be placed in `test/private/` (git-ignored); `npm test` converts them into
`test/private/out/`. Real MatWeb pages are not committed to the repository.

## Privacy

The extension has no network code of its own: it reads the page the user has open, stores data in the browser's local
extension storage and writes files to the Downloads folder. Permissions: `activeTab`, `scripting`, `downloads`,
`storage` (+ `offscreen` on Chrome/Edge).
